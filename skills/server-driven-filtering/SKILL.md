# 页面数据由接口决定

适用于本项目事实层、关联层及其他已有查询接口的页面交互。

- 筛选、搜索、取消勾选、反选、全不选、全选、清空和重置，都应将当前条件发送到相关接口；不能因为条件为空或全部取消，就停用查询、提前返回空数组或直接隐藏业务数据。
- 以接口契约区分空数组、缺省参数和空字符串。不得自行认定“全不选等于无结果”或把空数组改成“不限制”。契约不支持某条件时，明确指出缺口，不以本地过滤补齐。
- 地图、列表、图谱等各自使用对应接口的结果。不要在响应后按分类、品种、区域、关键词等业务条件再次过滤；总数、分页与记录必须保持一致。
- 查询键包含影响结果的条件；恢复此前条件也应重新请求，避免新鲜缓存跳过查询。React Query 的交互式业务查询可设置 `staleTime: 0`；同值重复提交查询时，需要显式刷新。
- 等待响应时可以保留上一批占位数据；新响应到达后以服务端数据替换。错误按现有接口错误机制展示，不伪造空结果。
- 只有明确的特殊要求允许前端业务过滤。纯展示操作（布局、动画、选中高亮、面板折叠）按展示需求处理，不因此额外发起无关业务请求。

## 本项目排查入口

- `src/pages/Dashboard/index.tsx`：事实层组装列表及地图参数。`CategoryIds: []` 时仍调用查询，不能再加入 `noCategories` 一类停用分支。
- `src/hooks/useFactQueries.ts`：事实列表 `/facts` 与地图 `/facts/points` 透传筛选结果，不做本地区域裁剪。
- `src/hooks/useRelationQueries.ts`：关联层 `/graph`、`/graph/points`、`/entities` 统一传递分类、关系类型、品种和搜索条件；分类和关系类型全不选时仍传空数组请求。

验证至少覆盖从有选项到全不选、取消最后一个条件、恢复已有条件，以及接口返回数据与页面业务数据一致。测试应检查查询是否启用、实际请求与参数，不能只检查按钮状态或查询键变化。
