# 需求范围与验收清理

- 只修改用户本次明确要求的内容，以及实现该要求必需的调用链、回归测试和明确要求更新的 skill。不要顺手调整其他功能、样式、文案、依赖或进行无关重构。
- 开始修改前查看工作区状态，区分已有改动与本次改动。保留用户或其他任务的已有代码，不覆盖、不回滚，也不把它们当作本次成果。
- 根据本次改动执行相关回归，必要时运行项目检查；交付前核对 diff，确保每处本次修改都有需求依据。
- 验收截图只作临时检查使用，回归结束后删除，不保存在仓库，也不作为最终交付物。优先写入临时目录，并清理本次生成的截图，包括未跟踪文件。
- 用户明确要求清理已有验收图片时，核实目录和引用后删除对应截图。不要删除产品图片、图标、Logo、用户原始参考素材或其他任务文件。
- 最终说明验证结果和必要限制即可，不为保留验收记录另建图片备份。
