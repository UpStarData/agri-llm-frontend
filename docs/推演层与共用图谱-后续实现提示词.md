### 4. 实现架构

- 建立 `src/components/graph/`，提供无业务请求、无宿主 store依赖的共用图谱。
- 建立 `src/modules/simulation/`，内含入口、pages、component、hooks、state、types、reports和隔离的demo。
- 建立 `src/integrations/simulation/`，由宿主传入农业种子、service、主题、返回/引用跳转和可选地图能力。
- 推演模块不得直接 import `src/store.ts`、Dashboard、农业详情或宿主 request。使用注入的 service和回调。真实API实现可位于接入层，沿用现有认证和错误机制，不改 `src/api/request.ts`。
- 服务端任务状态优先放 React Query，模块本地状态仅存草稿/选择/阅读位置。Query key包含 run_id、环境和查询条件，不能跨任务混用缓存。
- 服务层直接使用后端真实字段，不建立整套 `toXxx` 视图模型。共用图谱用 accessor/Pick读取原始记录；D3 的坐标/速度放独立渲染记录，不能污染业务响应。
- 顶层推演入口与既有 fact/relation 地图Mode解耦。做最小应用壳层接入，不给所有地图状态表硬塞simulation，也不重构无关导航。模块懒加载，任务/报告地址应能恢复。
- React组件用const，Props用interface IProps；单个TSX尽量≤500行，拆出详情、Modal、Drawer、工具结果展示等。优先antd/pro-components，按skill处理表单，不把上游五千行报告组件整体搬入。
- 不引入Vue运行时。必要的D3、Markdown/富文本等依赖先核对现有能力，只新增本次必需的依赖。

### 5. 共用图谱与关联层替换

迁移并改造GraphPanel的力导向、缩放、拖动、多边曲线、自环、标签、刷新、最大化和详情事件。关联层仍取现有 `/graph`，地理视图仍取 `/graph/points`；业务查询与详情链保持原行为。

必须实现：

- 节点/关系ID保留，方向按接口字段；分类色与业务字典一致，四类本体图例；标签开关默认开。
- 点击节点高亮自己、一级邻居和相连边，其余淡化；空白清空选中；点击边回调模块详情。
- 缩放和平移不改变数据查询范围。业务筛选/搜索/清空/恢复仍请求接口；不得前端过滤业务结果或根据“全不选”停用查询。
- 每个graph/context或run+snapshot保存布局和视口，稳定ID增量更新；主题、选中、标签变化不重建整图、不重新排列所有节点。
- 推演新增节点/边由后端来源字段决定，橙色虚线呈现；旧关系变化有依据；不得按数组位置或计时器制造新数据。
- 无地理坐标节点也显示；中文标签、同端点多边、双向边、自环、不完整端点数据按明确规则处理。缺失端点作为响应一致性问题处理，不伪造节点，不偷偷改变业务总数。
- ResizeObserver、force simulation、全局监听和计时器正确清理；多实例SVG defs ID避免冲突。
- 用约30、250、500节点/1500边样本验证性能，记录实测设备与结果，不宣称SVG必然更快或已支持任意规模。

原型GraphPanel中的分批揭示计时器、按度隐藏节点、window全局缓存不得原样带入生产。动画只能展示后端确认的增量，不修改业务范围和数量。

### 6. 发起页、种子、配置、历史

- 三栏：左侧历史、中间富信息输入、右侧统一推荐列表；面板显示控制按PRD接入。
- 事实/本体/关系三个详情入口带入明确种子ID与来源计数，不自动将整个地图或分页列表当种子。
- 种子清空/恢复仅作用于未提交草稿，不删现实数据、不影响附件；这是PRD明确的本地操作例外。依赖种子的推荐查询仍由后端提供。
- 输入支持文本、图片、图文粘贴并保留图片。附件本期最多一个，PDF/Word/Excel/Markdown；上传、解析中、失败、删除均有状态，失败附件不算有效输入。
- 上传/解析不阻塞编辑。默认解析中禁提交；失败时有系统种子或文本可继续。至少一类有效输入方可发送；禁止重复提交，失败保留输入。
- 配置：历史1/3/6个月默认3；10–40轮默认40，每轮1天；双环境/单市场/单协作；专家/数据报表均可选。配置摘要显示于顶部，创建后固化。
- 默认报告风格按PRD采用专家；不能因为原型默认为data就改变它。
- 推荐为统一3–8条，相关在前、热门在后；已有输入时替换先确认。推荐内容、热度与封面由后端提供，不在生产硬编码样例。
- 历史按创建时间倒序，每批10条无限加载；按运行/完成/失败打开对应页面。标题≤30字、省略hover全文、时间MM-DD HH:mm，支持PRD标题修改。
- 刷新/新标签页可恢复任务；切换现实层保留其原状态；进入新草稿不覆盖正在进行的任务。其他来源的新上下文不得无提示覆盖用户已编辑草稿。

### 7. 七阶段及任务状态

发送创建任务，后端默认连续准备阶段1–5；阶段5完成等待用户“开始推演”；所需环境成功完成阶段6后才开放“生成报告”；阶段7完成后开放“进入深度互动”。前端不靠动画完成阶段，不因组件挂载自动重复执行启动命令。

逐阶段实现：

1. 本体确认：阶段状态、本体/关系类型及对应清单、预加载图谱、日志。
2. GraphRAG：任务现实快照、本体/关系/类型数量、增量图谱及日志；按历史周期由后端取数。
3. Agent：生成数量、预期数量、关联话题、人设列表与详情；初始状态、行为规则、预置/新增来源按后端显示。
4. 配置：模拟时长、每轮时长、总轮次、活跃配置、Agent参数。算法参数只读：0.6/0.3/0.8/0.7/0.2；不添加调参功能。
5. 激活：叙事方向、3–5话题、Agent激活序列、环境、初始事件及初始状态。开局设定不计作已执行事件。
6. 推演：两环境独立ROUND/TIME/ACTS，环境可用动作只读面板、总事件与分类统计、混合时间线、固定日志、后端返回的指标变化、模拟图谱增量。
7. 报告：章节进度、耗时、工具次数、逐章内容、迭代/调用/结果追踪、最终报告。

农业动作按附件：市场INQUIRE/QUOTE/TRADE/ADJUST_PRICE/RESTOCK/PROMOTION/MONITOR/IDLE；协作NEGOTIATE/SIGN/INFO_EXCHANGE/LOGISTICS/QUALITY_CHECK/POLICY_PUBLISH/POLICY_MONITOR/IDLE。前端展示后端的可用列表，不执行农业决策、不把动作数量等同事件数量。

事件类别为市场交互、协作沟通、物流动作、政策事件、异常事件、促销活动、状态变化；类型与计数以接口为准。双环境事件按模拟时间及后端稳定序号排列，不能根据到达顺序推断因果。用户向上阅读时暂停强制滚动，新内容有提示，可回到最新。

阶段/任务/环境/报告分开状态。断线≠任务失败；重连先补权威快照并按事件ID/序号去重；切换任务取消旧订阅，忽略迟到响应。WS/SSE/轮询放service中，页面不绑定传输细节。

文档支持的业务失败显示原因与已完成阶段。暂停、重试、停止等命令仅在后端明确提供语义时接入，不创造可点击但无效的按钮。不要为满足旧MiroFish按钮而增加本期功能。

### 8. 两种报告和深度互动

报告由后端生成，模型提示词/工具选择/规则计算不在前端执行。3–8章动态规划，不固定成榴莲案例章节。

专家报告：受控Markdown渲染、标题/表格/引用、数据引用和声明式图表/图谱组件；正文按PRD的20–35个中文字/行舒适宽度处理，保留可读性和长内容滚动。

数据报表：后端交付多页HTML或文档URL及资源/组件/引用清单；有封面、内容页、可选附录、页码、上一页/下一页、键盘翻页、指标与图表交互。允许后端使用受控模板生成，不将前端写死样例当通用报告。具体HTML交付字段和组件挂载协议先查真实接口，没有则作为契约草案明确记录。

HTML必须在隔离容器中运行，不将任意生成脚本注入宿主DOM；只允许受控脚本资源/声明式组件，不把认证信息传给文档。消息桥校验来源frame、会话、run_id及类型，仅开放引用/页码/章节/选中文本等必要事件。组件挂载点接入共用图谱与可选地图能力，不执行模型生成的React代码。

如果后端仅能返回最终HTML，生成期间展示已到达章节草稿与真实追踪，成品就绪后展示HTML，不伪称最终HTML已实时生成。增量更新不整页刷新或丢失阅读位置。

图谱/2D地图/3D地球仅在后端数据与宿主能力支持时显示。需要复用地图时只提取必要的无状态渲染能力或注入view，不让推演依赖整个Dashboard，也不改变既有地图业务行为。

报告过程六类工具结果：快速检索、全景搜索、深度洞察、主体访谈、指标查询、图谱变化。分别提供PRD要求的列表/Tab/受访者Q&A/时序/新增节点与关系及Raw Output展示。只展示后端明确可公开的结构化结果与解释摘要，不要求模型暴露隐藏思维链。

报告内来源链接打开当前run的事实/本体/关系/推论详情，模拟ID不能误发到现实详情接口。深度互动采用左报告右对话，发送章节、选中文本、所点引用及对话上下文；保留历史、允许清空对话且不影响推演。主体访谈接已有能力，不额外扩成无关聊天产品。

封面A–E按附件生成/展示，主题数据和SVG来源由后端负责；封面配色局部生效，不覆盖宿主主题。不增加运行后的报告类型切换。封面失败用标题，图表失败用数据表；缺少静态图时不伪造截图降级。

### 9. 接口缺失时如何继续

- 先列出真实已存在接口与缺失能力。不要将MiroFish的project_id/simulation_id/report_id自行改名冒充农业run_id契约。
- service草案可覆盖：历史、创建、上传解析、任务快照/阶段、图谱、Agent/配置、启动、环境与事件、日志、报告生成/事件/成品/引用、对话与历史。
