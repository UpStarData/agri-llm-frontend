# 农业产业链数据大屏技术方案

> 本文为目标技术方案，不代表所有业务功能已实现。本轮工程基础与后续接入范围见 `README.md` 和《页面架构与接口接入》。项目路径为 `/Users/lll0716/Desktop/project/agri-llm-frontend`，采用 React 19、Ant Design 6 与 Less，具体版本以 package-lock.json 为准。

## 1. 目标与范围

本项目是以地图为核心的数据叙事大屏，不建设通用 GIS 平台。页面由事实层、关联层、右侧详情面板、AI 分析面板和常规统计图表组成。

数据验收以真实记录为准：至少 5,000 条可去重、可追溯的事实，4,000 个实体实例和 3,000 条真实关系。视觉密度点是由事实地理锚点派生的展示数据，不等同于真实事实，不能参与统计或打开事实详情。

地图默认的视觉预算为：全球约 50,000 个密度点、中国约 40,000 个、省区约 30,000 个。三个层级为切换视角，不要求同时显示 120,000 个粒子。

## 2. 技术选型结论

推荐使用以下组合：

```text
React + TypeScript + Vite
├─ deck.gl + GeoJSON：地图视图、边界、点、图标、关系线和密度效果
├─ MapLibre GL JS（按需）：矢量瓦片、道路、地名、卫星或栅格底图
├─ ECharts：趋势、雷达、柱状、指标卡等非地图图表
├─ Zustand：界面交互状态
├─ TanStack Query + Axios：服务端数据请求、缓存、失效和竞态处理
├─ dayjs：时间区间、时区和展示格式
├─ Ant Design：抽屉、卡片、按钮、表单、空状态等业务组件
├─ Less：全局样式、组件样式、变量和混入
├─ ahooks（按需）：防抖、节流、异步状态、持久化等通用 Hook
└─ 后端空间能力 / Turf.js：粒子生成、边界校验和预聚合
```

地图首版采用 **deck.gl + GeoJSON**，不需要一开始接入 MapLibre。deck.gl 的 `MapView` 已提供 Web Mercator 投影、拖动和缩放；GeoJsonLayer、ScatterplotLayer、IconLayer、TextLayer、LineLayer、PathLayer 和 ArcLayer 在同一视口内渲染，地图对象会始终跟随平移和缩放。

当产品需要道路、地名、卫星图、在线或离线矢量瓦片、多级底图样式时，再接入 MapLibre GL JS。MapLibre 负责底图和相机，deck.gl 使用官方 MapLibreOverlay 叠加数据图层。不要让两个地图组件分别处理拖动并互相同步状态。

ECharts 保留给普通统计图表，不作为本项目地图的主实现。AntV L7 可以覆盖本项目需求，但在本方案中不选用：团队已经将 React、deck.gl 图层和事实/装饰层边界作为主设计，deck.gl 的图层、拾取和性能控制模型更直接。若团队已有成熟 L7 实践或强依赖 L7/高德生态，可重新评估 L7。

## 3. 三种地图方案比较

| 维度 | ECharts 地图 | deck.gl + GeoJSON / MapLibre | AntV L7 |
| --- | --- | --- | --- |
| 3 万至 5 万视觉点 | 可用 Canvas 实现，特效、线和交互叠加后需重点调优 | 适合 GPU 批量点渲染，是首选 | WebGL 批量渲染，可行 |
| 4,000 实体和 3,000 关系 | 可实现，复杂图标、标签和关系交互维护成本较高 | 图标、文字、点、线、弧线分层清晰 | 图层表达丰富，可实现 |
| 拖动、缩放、层级切换 | 可做，但地图叙事和多层拾取需自行约束 | 与地理视口、图层拾取模型天然匹配 | 可做，依赖 Scene 与地图服务模型 |
| 真实与装饰数据隔离 | 需要严格规范 series 和事件 | 通过独立图层和 `pickable` 明确隔离 | 通过独立图层和事件管理隔离 |
| 本项目建议 | 仅用于普通图表 | **推荐** | 有成熟团队经验时的备选 |

## 4. 依赖是否需要引入

### 4.1 首期应引入

| 依赖 | 是否引入 | 作用与约束 |
| --- | --- | --- |
| React、TypeScript、Vite | 是 | 项目基础；TypeScript 需要覆盖接口 DTO、领域模型与图层数据类型。 |
| deck.gl | 是 | 首期就接入并完成全量压力验证，不能留到地图功能末期。 |
| GeoJSON 边界数据 | 是 | 首期提供全球、中国、省区边界及版本管理。它是数据资产，不是 npm 依赖。 |
| Axios | 是 | 统一 `baseURL`、超时、取消请求、错误标准化、鉴权和响应拦截。 |
| TanStack Query | 是 | 管理地图查询、详情、统计、关系邻域的缓存、失效和竞态。 |
| Zustand | 是 | 保存选择态、筛选态、地图层级、面板开关和临时视图状态。 |
| dayjs | 是 | 统一时间筛选、展示、时区和区间边界。 |
| ECharts | 是 | 只按需导入趋势、雷达、柱状等统计组件。 |

### 4.2 建议首期引入，但控制边界

| 依赖 | 是否引入 | 作用与约束 |
| --- | --- | --- |
| Ant Design | 建议 | 用于 Drawer、Card、Button、Select、DatePicker、Table、Skeleton 等复杂业务组件；使用按需导入并以主题 token 统一大屏风格。地图覆盖物不要直接套复杂 AntD 组件。 |
| Less | 建议 | 作为项目自有样式的唯一主方案，用于布局、间距、颜色、层级、组件样式和大屏适配；提供 `variables.less`、`mixins.less` 与全局入口。 |

### 4.3 按需引入

| 依赖 | 是否引入 | 作用与约束 |
| --- | --- | --- |
| ahooks | 按需 | `useDebounceFn`、`useThrottleFn`、`useRequest`、`useLocalStorageState` 等可减少样板代码；请求数据的缓存和生命周期仍由 TanStack Query 负责，不要让 `useRequest` 与 Query 管理同一接口。 |
| MapLibre GL JS | 按需 | 只有需要真实瓦片底图时引入。 |
| Turf.js | 按需 | 可用于原型和低频校验；50,000 粒子的空间采样与边界校验应放在后端或 Web Worker，不能放在 React 渲染循环。 |

### 4.4 推荐的接入顺序

可以先完成 React + TypeScript + Vite 的工程骨架，再逐步加入其他依赖；但 `deck.gl + GeoJSON` 应在第一个地图功能迭代加入，用全量视觉压力数据验证。不要先完成大量面板和动效、最后才发现地图方案在目标设备上不达标。

推荐顺序为：项目骨架与 TypeScript 规范 → Axios/Query/Zustand → deck.gl 与 GeoJSON 压力原型 → Ant Design 与 Less 样式基础 → ECharts → MapLibre（如需要）→ ahooks 和 Turf.js（按功能需要）。

## 5. 前端架构

```text
src/
├─ api/                 # Axios 实例和大屏接口请求
├─ pages/
│  └─ Dashboard/
│     ├─ index.tsx      # 唯一大屏页面
│     └─ index.less
├─ components/          # 详情、筛选、地图、统计、AI 等扁平组件文件
├─ utils/               # 日期、相机计算与 deck.gl 图层工厂
├─ hooks.ts             # 页面查询和视口防抖
├─ store.ts             # Zustand 交互状态
├─ queryClient.ts       # TanStack Query 配置
├─ types/               # 事实、粒子、实体、关系和查询口径
├─ styles/              # Less 变量、混入、全局样式和 AntD 主题
└─ App.tsx             # 全局 Provider；边界文件放在 public/boundaries
```

首版采用扁平结构：`Dashboard` 只保留页面入口与页面样式；可视组件全部放在根级 `components/`，地图图层与地图工具保持为根级单文件。不要为每一个组件创建文件夹，也不要为单页项目预设 `features/`。当未来出现第二个独立页面或一个模块被多个页面复用时，再按实际复用关系拆分目录。

事实层和关联层共用一个 Dashboard 与一个 MapCanvas，模式切换只改变图层和面板内容，保留相机、区域、时间和选择上下文。

状态职责必须分开：

- Zustand 只保存 UI 交互状态，如当前层级、选中事实/实体/关系、筛选条件、详情抽屉状态、图层显隐和当前相机快照。
- TanStack Query 保存服务端状态，如事实、实体、关系、统计、边界和详情数据。
- deck.gl 管理高频地图绘制与相机事件；拖动中的相机变化不应每帧写入全局状态或触发服务端请求。拖动结束并满足阈值后，再按需以视口查询数据。

## 6. 地图图层与交互边界

| 数据类别 | 数据身份 | 推荐图层 | 是否可点击 | 统计和详情规则 |
| --- | --- | --- | --- | --- |
| 行政边界 | 边界数据 | GeoJsonLayer | 区域选择时可点击 | 只用于范围和区域下钻，不计入事实、实体、关系统计。 |
| 真实事实 | `factId` | ScatterplotLayer；低缩放可用聚合层 | 是 | 只按唯一 `factId` 计数；点击进入事实、证据和来源详情。 |
| 视觉粒子 | `particleId`、`anchorFactId` | ScatterplotLayer；热力效果可选 HeatmapLayer | 否，`pickable: false` | 绝不参与事实统计、搜索、详情或关系端点；只保留其真实锚点引用用于审计。 |
| 实体实例 | `entityId` | IconLayer 或 ScatterplotLayer | 是 | 只按唯一 `entityId` 计数；打开属性、证据事实和关系邻域。 |
| 实体标签 | `entityId` | TextLayer | 通常否 | 仅显示重点节点；与实体共用身份。 |
| 普通关系 | `relationId` | LineLayer 或 PathLayer | 是 | 打开方向、端点、时间、关系类型和证据。 |
| 重点流向 | `relationId` | ArcLayer 或 PathLayer | 是 | 与普通关系共享真实关系身份，不能产生额外关系计数。 |
| 选中高亮 | 原对象引用 | 单独小图层 | 否 | 只改变呈现，不复制业务记录。 |

关系的两端必须是可追溯实体。无精确坐标的实体仍可出现在详情和图谱中；只有区域级位置时要标注为区域代表位置，不能伪造精确经纬度。

同一坐标存在多个事实时，点击后应展示候选列表或聚合成员，不能只打开堆叠最上方的一条记录。一跳关系默认重点显示；二跳按用户操作展开并限制返回量，避免全部图谱同时进入地图。

## 7. 视觉粒子与地理边界

视觉粒子应由真实事实地理锚点派生，推荐在后端预处理或 Web Worker 中生成。每个粒子最少保留：

```ts
type VisualParticle = {
  particleId: string;
  anchorFactId: string;
  anchorId: string;
  regionId: string;
  position: [longitude: number, latitude: number];
  seed: string;
  generatorVersion: string;
  boundaryVersion: string;
};
```

生成规则：以事实锚点为中心生成候选点，按照所属 Polygon 或 MultiPolygon 校验点位，处理岛屿、孔洞与狭长区域；固定随机种子，以保证同一筛选条件下粒子稳定。地图拖动和缩放只改变相机，不重新随机生成。

需要分别验收两类边界正确性：

1. 粒子中心不越界：所有粒子坐标都在所属行政区内。
2. 视觉不越界：半径、光晕和热力扩散不跨越边界。

第二项不能只依赖中心点校验。首版可为近边界粒子留安全距离，并在当前选中行政区域使用 GPU mask 做裁剪。热力图会在视口变化时重新聚合，且核扩散更容易越界；因此首版优先使用不可点击的 ScatterplotLayer 粒子，HeatmapLayer 作为专项验证后的可选增强。

## 8. 数据协议建议

所有查询使用统一上下文，并让响应回传数据与边界版本：

```ts
type QueryContext = {
  datasetVersion: string;
  level: 'world' | 'country' | 'province';
  regionId?: string;
  time: {
    field: 'eventTime' | 'publishedAt';
    from: string;
    to: string;
  };
  filters: {
    commodityIds?: string[];
    entityTypes?: string[];
    relationTypes?: string[];
    sourceIds?: string[];
  };
  viewport?: {
    bbox: [number, number, number, number];
    zoom: number;
  };
  statsScope: 'region' | 'viewport';
};
```

| 能力 | 建议接口 | 返回或规则 |
| --- | --- | --- |
| 行政层级和边界 | `GET /regions`、`GET /boundaries` | `regionId`、父级、层级、bbox、边界版本、简化级别。 |
| 地图查询 | `POST /map/query` | 真实点或聚合点、可定位实体、展示关系；明确截断标记和返回预算。 |
| 事实检索与详情 | `POST /facts/search`、`GET /facts/:id` | 稳定排序、游标分页、去重总数、地理锚点、完整证据链。 |
| 实体和关系详情 | `GET /entities/:id`、`GET /relations/:id` | 属性、端点、有效时间、证据和事实引用。 |
| 统计 | `POST /stats/query` | 基于真实记录去重，返回统计口径、时间字段、区域或视口范围。 |
| 空间聚合 | `POST /aggregates/query` | 行政区或网格聚合、真实 `factCount`、成员查询入口。 |
| 关系邻域 | `POST /graph/neighborhood` | 根实体、深度、方向、筛选、节点/边预算、截断和游标。 |
| 视觉密度 | `GET /visual-density` | 与真实记录独立；返回生成版本、边界版本、锚点映射和算法/种子。 |
| 数据审计 | `GET /dataset/manifest` | 事实、实体、关系去重数，证据覆盖率、关联完整性和定位覆盖率。 |

时间必须同时支持事实发生时间、来源发布时间和入库时间；接口要明确使用的字段、时区和半开区间 `[from, to)`。坐标统一采用明确坐标系和 `[longitude, latitude]` 顺序。

统计时 `factCount`、`entityCount`、`relationCount` 分别按自身 ID 去重。事实关联多个实体或来源时，数据库关联查询不能导致事实重复计数。粒子接口不能作为任何统计的输入。

一跳和二跳关系请求建议包含：

```ts
type NeighborhoodRequest = {
  rootEntityId: string;
  depth: 1 | 2;
  direction: 'in' | 'out' | 'both';
  relationTypes?: string[];
  time?: QueryContext['time'];
  maxNodes: number;
  maxEdges: number;
  cursor?: string;
};
```

二跳只返回由真实边组成的路径，不能把 A→B→C 推断为一条真实 A→C 关系。响应中的每条边都必须有端点与证据引用；截断时返回 `truncated: true` 和继续查询方式。

## 9. 数据可追溯与推演边界

事实至少保存来源标识、来源 URL 或文档定位、原文摘录、发布时间、采集时间、内容校验信息和可信度。多个来源印证同一事实时，应保留多条证据但只计一条去重事实。

AI 面板引用数据时应返回引用事实/来源；模型的总结、建议和预测需要展示其数据版本与引用范围。

## 10. 性能设计与验收

目标设备和最终大屏分辨率是性能验收基准。验收负载至少包括当前层级最大视觉粒子、真实事实对应要素、4,000 个实体、3,000 条关系、统计图表和详情面板同时存在。

建议验收门槛：

| 项目 | 建议门槛 |
| --- | --- |
| 连续交互 | 连续 10 分钟拖动、缩放、切层与打开详情，无崩溃或 WebGL 上下文丢失。 |
| 交互帧耗时 | 稳态交互 P95 不高于 33ms，目标接近 60fps。 |
| 选中反馈 | 高亮或请求加载反馈不高于 100ms；命中缓存的详情目标不高于 200ms。 |
| 已缓存切层 | 目标在 1 秒内稳定呈现。 |
| 地理正确性 | 点、线与边界持续贴合；粒子中心越界为 0；边界附近视觉溢出专项检查。 |
| 数据隔离 | 粒子数量变化不能改变事实、实体、关系统计；粒子不可点击。 |

实现约束：稳定保留 deck.gl 图层 ID 与数据引用；筛选结果使用 memoization；选择高亮放在独立小图层；不在每帧 `onViewStateChange` 中做数组过滤、空间计算或接口请求；标签和动画只保留重点对象；在最终设备上调整设备像素比、光晕、标签数量和弧线分段。

## 11. 风险与控制措施

| 风险 | 控制方式 |
| --- | --- |
| 首次使用 deck.gl | 在第一个地图迭代建立全量压力原型，验证点、线、图标、拾取、边界和目标设备性能。 |
| 粒子视觉越界 | 后端/Worker 预生成与点位校验；边界安全距离；当前区域 mask 专项测试。 |
| 热力图拖动卡顿 | 首版默认粒子散点；热力图独立压测，使用合理纹理尺寸和防抖。 |
| 大量标签、光晕、动画拖慢页面 | 设置重点对象预算，按需关闭动画并在低性能设备降级。 |
| 地图与统计口径不一致 | 所有查询共享 `QueryContext`、版本和范围；统计只使用真实记录。 |
| 事实、实体、关系缺少证据 | 数据导入与 `dataset/manifest` 审计证据覆盖率和悬空引用。 |
| 依赖职责重叠 | Query 管服务端状态，Zustand 管 UI，ahooks 不重复管理 Query 请求；Ant Design 主题由 `ConfigProvider` 管理，Less 只负责项目自有样式。 |

## 12. 最终建议

项目先搭建 React + TypeScript + Vite 的工程骨架，接入 deck.gl 和版本化 GeoJSON；后续建立全量压力场景。Axios、TanStack Query、Zustand、dayjs 同期引入。Ant Design 6 使用 `ConfigProvider` 的 token 定制主题，Less 负责项目自有布局与组件样式。ECharts 只服务统计图表。ahooks 已用于容器尺寸观察；Turf.js 和 MapLibre 按明确功能需求加入。

首版地图采用 deck.gl + GeoJSON 是可行且推荐的方案；当底图需求从“行政边界背景”扩展到“道路、地名、在线/离线瓦片或卫星图”时，再接入 MapLibre，而不需要改动业务数据模型或 deck.gl 图层架构。
