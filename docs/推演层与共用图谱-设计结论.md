# 推演层与共用图谱：设计结论及实施边界

日期：2026-10-16。用途：本次设计讨论的交付稿，供后续前端实现与后端对接使用。本轮只新增设计文档，不实施业务功能。

## 1. 已确定的结论

1. 关联层现有 ECharts 关系图谱确定替换为参考 MiroFish 的 D3 图谱实现。此处替换的是非地理关系图谱，不替换 deck.gl 2D/3D 地图。
2. 推演层在当前 React 项目内作为独立模块实现；现在不新建项目、不发布 npm 包、不嵌入整个 Vue 工作台。未来有实际复用需求时再抽离。
3. 两层复用图谱渲染和基础交互，分别管理数据查询、业务详情和任务状态。
4. 第一期同时支持专家 Markdown 与数据报表 HTML。用户最新明确要求覆盖 PRD 中“数据报表后期支持”的限制。
5. 发起页可选择报告风格；点击发送成功创建任务后锁定。运行、完成、打开历史报告、深度互动时都不能切换风格。提交进行中也禁止修改，提交失败且未创建任务时保留可编辑草稿。
6. 后端由后端同事负责。前端负责业务界面、状态展示、接口接入、图谱与报告交互，不在浏览器实现模型推演、GraphRAG 构建或农业计算规则。
7. 其他未提及模块不改。允许的宿主接入改动仅限顶部入口、三个详情中的发起入口、上下文传递、返回恢复及必要的共用渲染能力提取。

### 3.2 不能当成真实能力的原型逻辑

- `source/frontend/src/api/demo.js`、`builtinFlow.js` 拦截接口，以固定样例返回图谱、角色、运行进度、报告和问答；没有调用真实模型。
- `Home.vue` 的历史周期、轮次、环境控件没有完整进入启动参数；报告风格保存到 localStorage。正式版本须随任务保存，不能由全局偏好覆盖历史任务。
- `GraphPanel.vue` 有按阶段/定时器揭示预先加载节点的逻辑，以及启动后隐藏部分低度节点的演示逻辑。不能把这种呈现当作后端产生新本体，不能移植其业务节点裁剪。
- 原型图谱在特定更新时仍会清空 SVG 重建。正式版本应实现稳定 ID 的增量更新；动画只表现已返回的变化。
- `DataReport.vue`、`BuiltinReport.vue` 是内置案例布局，部分地球和关系图为示意 SVG，不等于通用 HTML 报告引擎或现有 deck.gl 地图复用已完成。
- 上游核心图谱使用 D3 + SVG；上游运行器仍有 `twitter/reddit` 平台字段。农业接口不能把“报价、交易、库存变化”仅映射为发帖文案。

### 3.3 当前 React 项目

- `src/components/map/RelationGraphCanvas.tsx`：约133行 ECharts 图谱，查询与渲染已分开；直接读宿主 store 的选中和主题，需要拆成容器与共用渲染器。
- `src/hooks/useRelationQueries.ts`：`/graph` 与 `/graph/points` 分开；图谱不应改为从地图可见节点生成。
- `src/components/DashboardHeader.tsx`：推演选项禁用。
- `FactDetail.tsx`、`EntityDetail.tsx`、`RelationDetail.tsx`：发起推演按钮尚未接通。
- `src/store.ts` 的 `Mode`、`modeStates` 等服务事实/关联地图。不要为了第三个顶层入口，给所有地图状态表硬加一个 simulation 分支。
- 历史选型理由见 `docs/关联层V1.3实现方案.md` §8：“沿用现有 ECharts，不新增图引擎依赖”。没有查到证明 ECharts 优于 D3 的专项评测。

## 5. 模块和依赖边界

建议结构（名称可按现有项目适度调整，不要求为了结构做无关重构）：

```text
src/
  components/graph/             # 可复用 D3/SVG 渲染与基础工具
  modules/simulation/
    index.tsx                  # 模块入口
    types/                     # 真实接口类型；未定契约单独标 draft
    pages/                     # 发起、运行、生成、报告互动
    component/                 # 模态框/详情/阶段展示/工具结果
    hooks/                     # 任务查询与订阅
    state/                     # 草稿、选择、阅读位置；任务数据优先放 Query
    reports/                   # Markdown、HTML 宿主与桥接协议
    demo/                      # 显式开发演示适配，不进入正式请求链
    styles/                    # 模块作用域样式
  integrations/simulation/     # 农业种子、鉴权请求、来源跳转、地图能力接入
```

依赖方向：宿主接入层→推演模块；关联层容器和推演模块→共用图谱。推演模块不得 import `src/store.ts`、Dashboard、农业详情组件或宿主 `request.ts`，宿主通过 service/回调/可选视图插槽注入。接口 DTO 保持后端字段，不引入重复视图模型。

图谱可通过原始记录及 accessor 读取 ID/端点/标签/颜色，或使用现有契约子集；D3 布局坐标放在独立渲染状态里，避免 D3 修改 React Query 中的业务响应。图谱内部不请求详情、不写宿主选择、不推导业务总数。

顶层导航与地图 Mode 分开：增加最小的应用层选择/路由接入，保留现有两层地图状态。新模块按需加载。历史任务和报告需要可恢复的地址/标识；路由方案依现有入口决定，不为此改造整站导航。切换模块清理展示订阅，但不调用后端停止；回到任务时重取权威快照。

从事实/实体/关系发起推演时只带入明确选择的 ID 与来源说明，不将当前整张图谱或当前分页列表自动当种子。已有任务不跟随现实层筛选变化；新草稿的来源变化不能无提示覆盖用户已编辑内容。必要时沿用原型的覆盖确认。

## 6. 图谱实现要点

- D3 force + SVG 作为首期路线；借鉴多边曲线、自环、拖动/点击区分、标签与工具栏。不能承诺必然比 ECharts 性能更好。
- 四类本体图例和关系颜色从当前业务字典查表；有向/无向关系保持接口语义，多条同端点关系保留各自 ID 和详情。
- 节点选中：自身、一级邻居、相连边高亮，其他淡化；空白取消；边点击打开所属模块的详情。
- 标签开关默认开启；刷新显式重新请求；最大化还原、缩放平移、拖动、容器变化适配。
- 坐标、固定位置、缩放和平移按 graph/context 或 run + snapshot 作用域保存；同 ID 增量合并，不每次响应重排整图。主题、选中和标签变化不重启布局。
- 推演新增来源由后端标记，以橙色虚线呈现；既有关系更新显示变化/依据；不得用数组位置或时间推断“模拟新增”。
- 无坐标实体仍能进入关系图谱；地图位置不得伪造。
- 压测先覆盖冷启动约30节点、演示约250节点、500节点/1500边。后两项是工程验证样本，不是已确认业务容量或性能承诺。若达不到实际需求，再评估 Canvas/WebGL，而非直接扩展本期范围。
- 重复挂载、任务切换、全屏和卸载须清理 force simulation、observer、全局事件与计时器。

## 7. 数据报表的交付方式

### 7.1 文档能确定的部分

PRD §4.4.4 将报告定义为：后端/模型自主规划3–8章，逐章调用工具形成草稿，按锁定风格转化为 Markdown 或多页 HTML。附件5 §5.2 给出内容、数据引用、内嵌组件的输出结构；§6.3允许图表配置复用封面配色。附件6给出多风格与分页展示基准。

因此采用“后端生成内容和成品、前端展示并承载交互”。不在浏览器调用模型，不把报告固定为两份内置榴莲模板。是否采用模板生成 HTML 可由后端决定，不能替后端规定只能使用固定 React 模板。

### 7.2 默认工程方案（建议，尚非已存在的后端接口）

- 专家报告：Markdown + 结构化引用 + 声明式组件描述；受控渲染 Markdown，图表/图谱通过组件注册表加载。
- 数据报表：后端返回 HTML 成品或文档 URL，并附版本、资源清单、页/章节标识、引用和交互协议。嵌入受隔离的报告容器，禁止将任意生成 HTML/脚本直接注入宿主 DOM。
- 可交互图谱/地图的复用方式：后端输出声明式挂载点或采用受控报表运行时，而非让模型生成 React 源码并在浏览器执行。组件数据从当前任务取得。
- 若需脚本交互，使用受控资源/独立运行时；宿主认证信息不传给报表。消息桥验证 frame 来源、会话、run_id、消息类型；仅允许翻页、引用打开、章节/选中文本同步等白名单事件。隔离页面为 opaque origin 时不能只检查 origin，要检查 source 和会话。
- 章节内容增量显示，避免每次流事件重载整份 iframe；最终 HTML 到达后保持阅读位置。后端若仅提供最终 HTML，生成期间展示章节草稿与真实进度，不伪称最终报表已经流式生成。
- 数据报表必须具有上一页/下一页和键盘翻页；输入/对话聚焦时不抢按键。引用能回到本任务的事实/本体/推论详情。可用数据支持时才显示2D/3D地理视图。
- 地图通过宿主可选视图能力或最小纯渲染组件接入，不把整个 MapCanvas/Dashboard 搬进模块；宿主未提供地图或缺少地理数据时说明无地理视图。
- 报告风格不可切换；封面A–E是已选报告的视觉配置，不是借此绕过风格锁定。

## 8. 前后端责任与契约清单

下列是对接需求，不是已实现 API，也不规定 HTTP 路径。正式字段名、分页和响应 envelope 以后端真实契约为准。

| 能力 | 后端提供 | 前端负责 |
| --- | --- | --- |
| 种子/推荐 | 接受三类 ID、校验可用性、按周期检索；推荐与统计结果 | 草稿输入、来源计数、推荐卡片及填入确认 |
| 附件/图片 | 上传、解析任务、状态、错误、资源ID | 单附件与图文粘贴、进度、删除、解析状态与有效性 |
| 创建任务 | 唯一 run_id、冻结配置/种子、幂等结果、真实阶段 | 防重复提交、成功导航、保留失败草稿 |
| 历史 | 每批10条、倒序、状态、开始时间、失败详情 | 无限加载、状态跳转、标题显示/编辑 |
| 准备 | 本体/关系/快照、Agent、配置、激活结果 | 七阶段展示、计数、详情与日志 |
| 运行 | 农业动作、每环境进度、事件流、权威统计、指标、图谱版本 | 时间线、独立状态栏、动作只读面板、图谱增量 |
| 报告 | 生成命令、章节、工具追踪、成品、引用、资源 | 按锁定风格展示、过程展开、组件渲染、降级 |
| 深度互动 | 任务上下文问答、引用、对话历史 | 当前章节/选中文本/引用上下文、发送、历史、清空 |
| 恢复 | 快照读取、事件游标/序号、重复事件判定、能力标记 | 重连去重、补齐快照、恢复阅读位置与状态 |

重点：

1. `run_id` 由后端生成；PRD 的日期序号格式作为业务要求对接，不在前端自增生成。
2. 区分 task、stage、environment、report 四级状态。内部示意：准备中→待启动→运行中→待生成报告→报告生成中→完成/失败；不要把该示意枚举当作后端字段。
3. 任务创建锁定报告风格必须由后端约束；仅隐藏前端切换按钮不够。
4. WebSocket 是 PRD 报告事件的参考方案，示例路径不是已验证接口。无论 WS/SSE/轮询，组件只消费统一 service 事件；PRD 事件包含 planning_start/done、section_start/done、llm_iteration、tool_call/result、report_done。
5. 命令与订阅分开，断线重连不得重新创建任务/重新生成报告。若后端用“建立连接即启动”接口，需具备幂等和恢复语义。
6. 完成报告的前提是所有选定环境已成功完成；一个环境失败不能伪装成完整双环境结果。
7. 指标单位、初始值、每轮值、变化幅度、事件类型和计数由后端决定；前端不从分页事件推导全量计数，不把未知值显示为0。
8. 草稿种子清空是本地输入操作；已实现的图谱/历史/事件业务查询仍遵守服务端筛选。所有相关搜索、重置、恢复都请求接口。
9. 模型提示词、Jev接入、Zep/OASIS选择、Agent预置库持久化、农业计算与证据抽取属于后端。前端不保存模型密钥、不硬编码模型调用步骤。

接口未提供时，可完成模块 UI、交互、service 类型草案和显式演示适配。生产接口缺失必须说明，不静默回退假数据，也不能称为真实联调完成。

## 9. 实施顺序和工作量

无需新增产品确认，按依赖顺序实施：

1. **契约和源码盘点**：记录基线、来源、许可、实际后端能力；建立模块入口和 service 边界。
2. **共用图谱与关联层替换**：先用现有 `/graph` 验证选择、详情、字典和位置保持，保持地图和其他模块行为。
3. **推演发起与任务恢复**：三栏、种子、富信息输入、单附件、配置锁定、历史与深链接。
4. **阶段1–6**：准备结果、Agent/参数/激活、环境状态、事件和图谱增量；真实任务状态驱动。
5. **阶段7及两种报告**：生成追踪、引用、Markdown、HTML交付和组件桥接；两种风格分别创建任务验收。
6. **深度互动与联调回归**：章节/选区上下文、引用详情、历史与失败恢复、性能、回归清理。

阶段拆分是交付顺序，不是削减本期两种报告或完整七阶段的范围。

粗估（单名前端、接口及时提供、复用现有组件，非承诺）：图谱3–5人日；模块/发起/历史4–6；准备和运行4–6；报告追踪、两种风格与引用6–10；互动、联调与回归4–6。总体约21–33人日，部分内容可重叠；后端等待不计入开发人日。这个范围比先前“仅迁移演示”的估算更接近完整 PRD。

## 10. 验收边界

- 关联层节点、关系点击仍进入原有详情；图谱查询与地图查询独立；全部取消筛选仍请求接口；已有用户修改保留。
- 四类图例、方向、多边、自环、中文标签、全屏、容器缩放、亮暗主题；增量后旧节点/视口稳定；选择不能重启整图。
- 事实、本体、关系三个发起入口；清空/恢复不影响附件或现实数据；来源切换不覆盖已编辑草稿。
- 文本、图片、图文粘贴不丢图；一个附件、解析中/失败/删除/其他输入可继续等状态正确；上传与提交无重复。
- 历史10条分页，运行/完成/失败各自恢复；刷新页面不生成新任务；返回现实层保留之前视图状态。
- 10–40轮、默认40、每轮1天、三种环境；报告类型创建后在所有入口不可改变。
- 单环境、双环境不同进度、异常、断线重复/乱序事件、返回任务；事件计数与动作数明确区分。
- 模拟新增橙色虚线并带来源；数据不进入现实查询缓存；任务之间不串图谱、日志、报告和对话。
- 两种报告分别端到端验收：真实章节事件、六类工具结果、引用、动态组件、HTML分页/键盘/隔离、Markdown正常阅读。
- 切换/重挂模块不会重启任务；后台推演不依赖页面计时器；订阅和图形资源及时释放。
- 缺少地理数据不伪造地图；封面失败用标题，图表失败用数据表，未知组件显示说明；无静态快照时不伪造降级截图。
- 正式数据与演示数据有明确边界；不把预设数值当真实推演。
- 运行适当的 typecheck/lint/测试/build，浏览器验收后清理本次截图；不修复无关历史问题，不保存截图作为交付物。
