# 页面架构与接口接入

## 决策

事实层、关联层使用一个 Dashboard 页面，通过 `mode` 切换，共用一个 MapCanvas。它们使用同一地理空间、时间筛选和选择上下文，切换时无需重新创建 WebGL 上下文、重载边界或恢复相机。`MapCanvas` 的组件位置和 key 保持不变。事实、实体和关系拥有独立 ID 和图层，页面共用不等于数据混合。

两种模式复用左右浮层组件，边缘留有安全距离，均可展开和收起。事实层左侧“数据概览”包含主指标和分组分类标签，另有独立的“地图控件”浮层；两个左侧浮层独立收展。关联层左侧仅显示“数据概览”。分类选中状态进入服务端查询，每次变化重新请求地图和统计；地图与右侧列表使用同一地图响应。分类体系目前仅为前端展示配置，后续需与后端分类 ID 对齐。地图控件配置为一行两列，支持球体/平面视角、全屏、缩放和复位，并可切换港口、事实源、影响力叠加层；总开关关闭后不显示地图操作和叠加层。事实层右侧标题为“事实项”，关联层右侧标题为“关联项”，关联层列表包含实体本体和真实关系。大屏使用双列记录卡片，点击后才打开“事实详情”或“本体详情”弹窗。地理视角切换仅在事实层显示，日期筛选两层通用。

## 请求约定

Axios 返回体当前直接为业务 JSON，无 `{ code, data }` 包装。如果后端采用包装结构，在 `api/dashboard.ts` 统一适配。Query 将 AbortSignal 传给 Axios；切换区域/日期后使用新的查询键，不用上一组筛选结果冒充当前结果。

当前参数示例：

```json
{
  "mode": "fact",
  "level": "province",
  "regionId": "430000",
  "time": {
    "field": "eventTime",
    "from": "2026-08-31T16:00:00.000Z",
    "to": "2026-09-24T16:00:00.000Z"
  },
  "filters": { "selectedIds": ["tag:高温", "tag:港口"] },
  "statsScope": "region",
  "overlays": ["ports", "factSources", "influence"]
}
```

`/stats/query` 使用相同的模式、区域、时间和筛选条件，但不发送 `overlays`。`/map/query` 响应可选 `overlays.ports`、`overlays.factSources` 和 `overlays.influence`；前两者每项至少有 `id`、`name`、`position: [经度, 纬度]`，影响力项也需要这些字段，可附加 `intensity`。前端仅绘制接口返回的点，影响力圆环为像素动画；其业务半径和强度口径需由后端另行定义。

日期由上海时区自然日转为 UTC `[from, to)`，结束日期在界面中含当天。拖动地图不会改变区域统计范围或逐帧请求。

| 路径（相对 /api） | 方法 | 当前结构 |
| --- | --- | --- |
| `/map/query` | POST | `{ datasetVersion, facts, entities, relations, overlays?, truncated }` |
| `/stats/query` | POST | `{ datasetVersion, factCount, entityCount, relationCount, updatedAt, trend: [{date, count}] }` |
| `/facts/:id` | GET | `Fact`，包含 sources 原文证据 |
| `/entities/:id` | GET | `Entity`，包含支撑 factIds 和可空 position |
| `/relations/:id` | GET | `Relation`，包含端点和支撑 factIds |
| `/graph/neighborhood` | POST | `{ datasetVersion, nodes, edges, truncated, nextCursor? }`；请求函数已准备，UI 待实现 |

所有细节类型位于 `src/types/index.ts`。地图和统计响应的 datasetVersion 不一致时会隐藏统计并提示；下一阶段应由后端支持显式固定数据快照，并让详情/邻域也返回或接收同一版本。当前未声称具备完整的一致性快照协议。

状态区分：接口未配置显示 `—`；接口返回计数 0 显示 `0`；失败展示错误；加载时展示骨架。后端必须按真实唯一 ID 去重计数，前端不从粒子、当前地图点数或分页结果推算总数。

## 后续边界

- 当前粒子工厂仅预留不可拾取图层。生成、锚点校验、所属行政区中心校验与光晕裁剪尚未实现，不能直接装载任意随机点进入正式大屏。
- 真实事实的多地理锚点、同坐标候选列表、无坐标实体列表、关系高亮/一跳/二跳的交互需在实际数据协议确定后补齐。
- 真实数据目标 5,000 / 4,000 / 3,000 和视觉点目标 50,000 / 40,000 / 30,000 是后续验收目标，本轮工程初始化不代表已达成。
- AI 服务需通过后端调用并携带引用；当前页面不展示 AI 分析入口。
- MapLibre 仅在需要道路、地名、真实瓦片等底图能力时接入。首版 deck.gl + GeoJSON 可以完成当前原型的边界型地图。
